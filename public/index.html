Product margin, corrected twice

  1. Course figure, wrong: 100%

    The course filtered cost to unsold stock, then summed it only for sold stock, so cost was always zero.

  2. Course figure after the first fix, still wrong: 82.4%

    With that filter fixed, cost came from inventory units, not the order lines that earned the sales. In this data, no order line points at a sold unit.

  3. Corrected: 50.7%

    Sales and cost now come from the same order lines, leaving out cancelled and returned items.

Four more faults

Snapshots could never record a change

They watched created_at, which never changes. They now check status and the shipped, delivered and returned dates.

Before: created_atNow: status and 3 dates

Session counts were yes-or-no flags

Each customer was counted within their own row, so every value was 0 or 1. The model now counts sessions.

Before: 0 or 1Now: 1 to 6

The customer table held one country

A filter left over from an exercise kept only Australian customers. The table now covers all 49,999.

Before: Australia onlyNow: every country

Some orders shipped before they were placed

Three order timestamps loaded without a time zone, so on a machine outside UTC the dates fell out of order. Staging now reads them as UTC.

Before: no time zoneNow: UTC

Smaller fixes: a longtitude typo, mixed-case column names, a user ID read as a float, and a Windows-only race when DuckDB installed its HTTP extension.

Does the marketing channel matter?

Search brings in 70% of customers. In every channel about 27% of customers have a completed order, so the channel decides how many customers arrive, not how likely they are to buy.

How it's built

The project runs on dbt-core 1.12 and DuckDB. There is no warehouse and no load step: dbt reads six CSV files over HTTPS during the build, so the whole thing runs with one command.

  1. 6 CSV sources and 1 seed
  2. 7 staging tables
  3. 2 ephemeral pivots
  4. customers and products

Two snapshots record changes to orders and inventory.

That run covers 47 data tests and 1 unit test, including a not-null test on product cost so a missing cost can't silently become zero. The one no-op is this page, declared as a dbt exposure so it shows up in the lineage. GitHub Actions runs the same build on every pull request, and this site is rebuilt from it on every push.

About the data

TheLook is a synthetic store published by Google; none of its customers are real people. The build reads DataCamp's copy over HTTPS, and the repository stores none of the raw files.

Two files are samples. order_items holds about half of all order lines, so dollar amounts here are partial and margins are not. events holds about 2% of events, so session counts are a relative signal only.
